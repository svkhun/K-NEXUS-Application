# วาง FlowSense × TrustGraph ในประสบการณ์ K+ — 17 ตุลาคม 2026

## สิ่งที่อ่านได้จากภาพอ้างอิง

ภาพที่ผู้ใช้ส่งเป็นภาพแอปจริงที่ปิดข้อมูลสำคัญแล้ว ใช้เป็นหลักฐานอ้างอิงด้านโครงหน้าจอในงานนี้ ไม่ใช่เอกสาร design system ของธนาคาร และไม่ใช่การยืนยันว่าโครงการได้รับอนุมัติให้รวมใน K+

- ภาพ 1: หน้าแรกแบ่งพื้นที่แนะนำด้านบนออกจาก “เรื่องสำคัญวันนี้” และ “ธุรกรรมด่วน” ผู้ใช้จึงรู้ว่าข่าวสารสำคัญกับปุ่มทำงานอยู่ตรงไหน
- ภาพ 2: หน้าธุรกรรมใช้บัตรบัญชีเป็นจุดตั้งต้น ปุ่มบริการเป็นวงกลม แถบล่างมีปุ่มธุรกรรมตรงกลางที่เด่นกว่าปุ่มอื่น
- ภาพ 3: โปรไฟล์มีทางเข้า “การเงินของฉัน” จึงเป็นตำแหน่งถาวรที่เหมาะสำหรับแผนเงิน
- ภาพ 4, 5, 7, 10: การเงินของฉันและรายการบัญชีมีสรุปรายรับรายจ่าย/สินทรัพย์อยู่แล้ว คุณค่าที่เราต้องสื่อให้เห็นคือแผนเงินล่วงหน้าและผลของการตัดสินใจ ไม่ควรขายเพียงการมีกราฟหรือสรุปย้อนหลัง
- ภาพ 6, 8, 9: งานกรอกข้อมูลใช้พื้นสว่างและส่วนหัวเขียว ข้อมูลบัญชี จำนวนเงิน และปุ่มยืนยันแยกชัดจากเนื้อหาอื่น

งานนี้วาดภาพประกอบและลายบัตรขึ้นใหม่ด้วย SVG ไม่บรรจุภาพถ่าย หน้าจอ หรือข้อมูลบัญชีของผู้ใช้ลงเว็บ/แหล่งโค้ด

## จุดขายที่ต้องเข้าใจจากหน้าจอ

“รู้เงินที่ใช้ได้ ถึงวันเงินเดือน และเห็นเงินที่เหลือก่อนตัดสินใจโอน”

FlowSense ตอบเรื่องเงินสำหรับชีวิตประจำวัน บิล และเงินสำรอง ส่วน TrustGraph แสดงสัญญาณที่ควรตรวจสอบเกี่ยวกับผู้รับ ข้อมูลสองชุดอยู่ในขั้นตอนตัดสินใจเดียวกัน แต่ไม่ตีความว่ารายได้น้อยเท่ากับมีความเสี่ยงถูกหลอกสูงขึ้น

ชื่อสำหรับลูกค้าใช้ “แผนใช้เงิน”, “ออมส่วนที่พร้อม” และ “ดูแลก่อนโอน” ชื่อโมเดลยังอยู่ในบริบทต้นแบบและรายละเอียด โดยไม่บังคับให้ผู้ใช้เข้าใจศัพท์ก่อนเริ่มทำงาน

## ทางเข้าที่ทำแล้วในต้นแบบ

| ตำแหน่ง | สิ่งที่ผู้ใช้เห็น | ไปทำอะไรต่อได้จริง |
| --- | --- | --- |
| หน้าแรก → เรื่องสำคัญวันนี้ | วันนี้ใช้เพิ่มได้อีก พร้อมยอดใช้แล้ว/งบทั้งวันและวันถึงเงินเดือน | ดูแผนเงิน ทดลองเปลี่ยนงบ และดูบิลที่กันไว้ |
| หน้าแรก → การแนะนำด้านบน | รู้เงินที่ใช้ได้ มั่นใจก่อนใช้ ก่อนโอน | เปิดแผนใช้เงิน |
| หน้าแรก → ดูแลก่อนโอน | รู้ความเสี่ยง เห็นเงินที่เหลือ | ทดลองผู้รับที่ควรตรวจเพิ่ม แล้วกดดูผลกระทบก่อนโอน |
| ธุรกรรม → ใต้บัตรบัญชีและปุ่มบริการ | การเงินของฉัน: ดูเงินที่ใช้ได้จริงถึงวันเงินเดือน | เปิดแผนเงิน |
| ธุรกรรม → จ่ายบิล | บิลที่กันไว้และยอดคงเหลือถูกเลือกในฟอร์ม | ตรวจผู้รับ ดูผลต่อแผนเงิน แล้วยืนยันเอง |
| โปรไฟล์ → การเงินของฉัน | ทางเข้าถาวรพร้อมแผนใช้เงินและเงินออม | ดูบัญชี แนวโน้ม บิล และการออม |
| การเงิน → แถบแผนใช้เงิน/แนวโน้มเงิน/เงินออม | แยกงานปรับแผน ดูกราฟ และออม | เปลี่ยนส่วนได้โดยไม่ต้องกลับไปหาเมนูใหม่ |
| ก่อนโอน → ตรวจสอบข้อมูล | ผู้รับ ยอดโอน งบก่อน–หลัง บิล และเงินสำรอง | ตรวจสอบตามสถานการณ์ ยกเลิก หรือยืนยันตามนโยบายเดิม |

กรณี “จ่ายบิล” เป็นการตั้งรายการจำลองจากบิลก่อนเงินเดือน ไม่ใช่การเชื่อมผู้ให้บริการรับชำระหรือยืนยันว่าผู้รับเป็นเจ้าของบิล ผู้ใช้ยังต้องตรวจผู้รับและกดยืนยัน ส่วนการเลือกบิลไม่ลดคะแนนความเสี่ยงหรือปลดบัญชีที่ถูกระงับ

## ข้อเสนอหากรวมกับ K+ จริง

นี่เป็นแผนผลิตภัณฑ์สำหรับหารือ ไม่ใช่ความสามารถที่เชื่อมกับ K+ แล้ว

1. **หน้าแรก:** ใช้พื้นที่ “เรื่องสำคัญวันนี้” เป็นการ์ดหลัก พร้อมข้อความแนะนำเมื่อเริ่มเปิดตัว เช่น “ใหม่ วางแผนเงินให้พอถึงเงินเดือน” เมื่อผู้ใช้รู้จักแล้ว ให้แสดงข้อมูลที่ใช้ตัดสินใจได้แทนการโฆษณาซ้ำ
2. **การเงินของฉัน:** เพิ่มส่วนแผนเงินล่วงหน้าข้างสรุปรายรับรายจ่ายเดิม ให้เข้าถึงได้จากโปรไฟล์และหน้าบัญชี ผู้ใช้ที่ปิดการ์ดหน้าแรกยังกลับมาใช้งานได้
3. **ขั้นตอนโอน:** แสดงผลกระทบหลังผู้ใช้เลือกบัญชีผู้รับและยอดเงิน ก่อนยืนยัน การตรวจผู้รับทำงานในจังหวะเดียวกัน ผู้ใช้ไม่ต้องเปิดแอปช่วยเหลืออีกตัว
4. **การออม:** เสนอเฉพาะส่วนที่พร้อมหลังค่าใช้ชีวิต บิล และเงินสำรอง ผู้ใช้เปิดใช้งานและยืนยันเองทุกครั้ง รอบที่เงินตึงให้พักคำแนะนำออมเพิ่ม
5. **เมนูหลักจริง:** สามจุดข้างต้นอยู่ในโครง K+ เดิมได้ จึงไม่จำเป็นต้องเปลี่ยนแท็บหลักของ K+ เพื่อเพิ่มฟีเจอร์นี้ ต้นแบบใช้แท็บการเงิน/ออมเพื่อทดสอบความสามารถที่ทำงานได้ครบ ไม่แสดงบริการตลาดหรือสแกน QR ที่ไม่ได้ทำงาน

สิ่งที่ต้องเชื่อมเมื่อพัฒนาเป็นฟีเจอร์จริง ได้แก่แหล่งข้อมูลบัญชีและบิลที่ได้รับอนุญาต การยืนยันผู้รับ/สถานะรายการของธนาคาร และการเก็บสถานะรายการอย่างถาวร ระบบปัจจุบันยังเป็นข้อมูลสมมติใน session

## ภาษาภาพที่ใช้แล้ว

- ภาพรวมใช้พื้นเขียวอมฟ้าไล่ลงสู่น้ำเงินเข้ม ปุ่มและตัวเลขสำคัญเป็นมิ้นต์อ่อน
- ใช้รูปทรงบัตรบัญชีและปุ่มวงกลมในหน้าธุรกรรม ลดการแยกข้อมูลทุกบรรทัดเป็นกรอบสีขาว
- หน้าวางแผนและออมใช้พื้นสว่างเฉพาะพื้นที่กรอกข้อมูล ส่วนหน้าตรวจรายการใช้ส่วนหัวเขียวและเนื้อหาสว่าง
- สีความเสี่ยงยังเป็นคำเตือนแยกจากสีแบรนด์ ไม่ทำให้สถานะที่ไม่พบสัญญาณกลายเป็นการรับรองความปลอดภัย
- ตัวเลขคำนวณจาก API/สถานะจริงของต้นแบบ ไม่มีจำนวนเงินหรือเปอร์เซ็นต์ผลลัพธ์เพิ่มเพื่อความสวยงาม
- พื้นฐานการจัดวางและฟอร์มอยู่ใน `banking.css` ส่วนภาษาภาพตามภาพอ้างอิงอยู่ใน `kplus.css` ใช้ขอบเขต `.kplus-experience` และปรับตามบทบาทองค์ประกอบ

## วิธีพิสูจน์เรื่องการค้นพบฟีเจอร์

ยังไม่มีการทดสอบกับผู้ใช้จริง ควรให้คนกลุ่มเป้าหมายทดลองโดยไม่ชี้ตำแหน่งปุ่ม แล้วสังเกต:

- บอกได้หรือไม่ว่าฟีเจอร์ช่วยอะไร หลังเห็นหน้าแรก
- หา “วันนี้ใช้เพิ่มได้อีก” และอธิบายความต่างจากยอดบัญชีได้หรือไม่
- เริ่มปรับแผนและกลับมาหาฟีเจอร์จากโปรไฟล์ได้หรือไม่
- เข้าใจหรือไม่ว่าการจ่ายบิลที่กันไว้ไม่ถูกหักงบซ้ำ
- เห็นและเข้าใจผลก่อน–หลังโอนก่อนกดยืนยันหรือไม่
- รายการปกติยังทำสำเร็จได้สะดวก และคำเตือนรายการเสี่ยงทำให้รู้ว่าต้องตรวจอะไรต่อหรือไม่

วัดเวลา จำนวนการแตะ การเลือกผิด การทำงานสำเร็จ และคำอธิบายของผู้ใช้ เปรียบเทียบกับหน้าจอก่อนปรับ ข้อมูล QA ของผู้พัฒนาไม่ใช่หลักฐานว่าอัตราค้นพบฟีเจอร์หรือการป้องกันมิจฉาชีพดีขึ้นแล้ว

## ผลตรวจต้นแบบรอบนี้

- Production build ผ่าน, ชุดทดสอบ JavaScript 13 ข้อและ Python 56 ข้อผ่าน
- ตรวจหน้าจอที่ความกว้าง 320, 390 และ 1440 พิกเซล รวมหน้าแรก ธุรกรรม การเงิน เงินออม และโปรไฟล์ ไม่พบการล้นแนวนอนในหน้าที่ตรวจ
- ตรวจทางลัดจ่ายบิล การเปิดเลือกผู้รับ การล้างบิลเมื่อเปลี่ยนผู้รับ และหน้าสรุปก่อนโอนทั้งรายการปกติ/รายการเสี่ยง โดยไม่ยืนยันโอนในรอบตรวจ UI
- ตรวจโหมดซ่อนข้อมูลและทางลัดถอนเงินออม รวมถึงตรวจคอนโซลรอบสุดท้าย ไม่พบ error/warning
- หน้ากรอกโอนย่อรายการผู้รับไว้ใต้ปุ่มเปลี่ยนผู้รับ และแยกสถานการณ์มูลค่าสูง/สัญญาณจำลองไว้ในส่วนเปิดดูเพิ่มเติม

ผลข้างต้นเป็นการตรวจการทำงานและการแสดงผลในเครื่อง ยังไม่ใช่ผลทดสอบกับผู้ใช้จริงหรือผลตรวจ deployment
