# เงินสำรองที่ผู้ใช้เลือกและการอธิบายสภาพคล่อง

## พฤติกรรมที่ทำแล้ว

ผู้ใช้ตั้งและยืนยันเงินสำรองได้จากหน้าแผนใช้เงินและหน้าออมเงิน ก่อนยืนยันมีปุ่มคำนวณผลต่องบที่ใช้เพิ่มได้วันนี้และเงินส่วนที่พร้อมออม ตัวเลขมาจากสูตรเดียวกับฝั่งเซิร์ฟเวอร์ที่ใช้หลังบันทึก ไม่ใช้การจำลองสูตรอีกชุดบนหน้าเว็บ

- ยอดเริ่มต้นอ่านจาก `emergency_buffer` ของโปรไฟล์สมมติ (ถ้าไม่มี ใช้ 12% ของเงินเดือนสมมติ และขั้นต่ำ 500 บาท) แสดงชัดว่ายังไม่ได้ตั้งเอง ไม่อ้างว่า AI แนะนำหรือเหมาะกับการเงินจริงของผู้ใช้
- ผู้ใช้ยืนยันยอดเดิมหรือปรับยอดได้ 500–10,000,000 บาท ทศนิยมไม่เกินสองตำแหน่ง ขั้นต่ำเป็นกติกาต้นแบบ ไม่ใช่มาตรฐานเงินฉุกเฉินสำหรับทุกคน
- เงินสำรองเป็นการเว้นเงินในการคำนวณ ไม่มีการล็อก ย้าย หรือเพิ่มยอดเงิน การลดสำรองเพิ่มพื้นที่งบได้โดยแลกกับเงินเผื่อฉุกเฉินที่น้อยลง
- จดจำแยกแต่ละบัญชีและ session ทดลอง รีเฟรชยังอยู่ เปลี่ยนสถานการณ์ทดลองยังคงค่าที่เลือกไว้ การรีเซ็ตบัญชีจะคืนค่าเริ่มต้น ไม่ใช่ข้อมูลที่เก็บถาวรในระบบธนาคาร
- งบรายวัน ยอดพร้อมออม และผลก่อนโอนอ่านค่าที่เลือกเดียวกัน ถ้าเงินสำรองเปลี่ยนหลังเปิดรายการโอน proof เดิมยืนยันไม่ได้ ต้องดูแผนใหม่ ไม่เปลี่ยนคะแนนเสี่ยงผู้รับ
- ใช้ CSRF และ idempotency ที่มีอยู่ ตรวจจำนวนเงินที่ API ฝั่งเซิร์ฟเวอร์ และคำนวณเพดานออมใหม่ก่อนหักยอดทุกครั้ง

`POST /api/v2/flowsense/reserve-preview` รับ `{account_id, amount}` แล้วคืน before/after โดยไม่บันทึกเงินสำรองและไม่เปลี่ยนยอดเงิน ส่วน `/reserve-preference` บันทึกค่าหลังผู้ใช้กดยืนยันเอง

## ทำให้เข้าใจว่าแผนช่วยอะไร

หน้าแรกนำเข้า “จัดเงินให้พอใช้ถึงวันเงินเดือน” หน้าแผนแยกยอดบัญชี → บิล → เงินสำรอง → เงินที่เหลือแบ่งใช้ พร้อมทางเลือกสามอย่าง:

1. ลดรายจ่าย: แสดงตัวอย่างลดวันละ 50 บาทตั้งแต่พรุ่งนี้ถึงวันก่อนเงินเดือน พร้อมเงื่อนไขว่าต้องลดได้จริง แล้วเปิดช่องทดลองงบ
2. ถอนเงินออม: แสดงตัวอย่างย้ายเงินเดิมเข้าบัญชีหลัก ยอดรวมไม่เพิ่ม ปุ่มพาไปเลือกจำนวนและยืนยันเอง ไม่มีการถอนอัตโนมัติ
3. ออมส่วนที่พร้อม: หากไม่มีส่วนเกินให้พักออมเพิ่ม ไม่ชักชวนให้กันเงินที่ต้องใช้ไปออม

ตัวอย่างเป็นคำอธิบายและการวางแผน ไม่ใช่หลักฐานว่าผู้ใช้ลดรายจ่ายจริงหรือได้รับสภาพคล่องเพิ่มจากโมเดล

## สีตามภาพอ้างอิง K+

ใช้พื้นเขียวอมฟ้า/น้ำเงินเข้มสำหรับภาพรวม พื้นงาช้าง/ขาวสำหรับตัวเลขและงานกรอก แยกบริการด้วยมิ้นต์ เขียวมะนาว ส้มคอรัล ฟ้า และเหลือง แทนการใช้สีมิ้นต์ทุกส่วน เงินสำรองใช้เหลืองทอง บิลใช้คอรัล และเงินที่เหลือแบ่งใช้ใช้เขียวมะนาว ทุกสีมีข้อความกำกับ ไม่ใช้สีเพียงอย่างเดียวสื่อความหมาย

## การตรวจสอบ

ชุดทดสอบ Python 62 ข้อและ JavaScript 13 ข้อผ่าน รวมกรณี preview ไม่แก้สถานะ บันทึกแล้วผลตรงกัน ยอดเงินไม่เคลื่อน การแยก session/บัญชี การตรวจขอบเขต/CSRF การรีเซ็ต การกันออมเกิน และการไม่ยอมรับรายการโอนที่ใช้แผนเงินสำรองเก่า

Production build ผ่าน ตรวจเบราว์เซอร์ที่ความกว้าง 320, 390 และ 1440 พิกเซล: บันทึกเงินสำรองแล้วรีเฟรชยังคงค่า ตัวเลข preview ตรงกับหลังบันทึก ทางเลือกถอนพาไปโฟกัสช่องถอนโดยไม่ย้ายเงิน กรณีจำนวนเงินยาวไม่ล้นจอ และโหมดซ่อนข้อมูลซ่อนตัวเลขของแผนใหม่ได้ทั้งหมด คอนโซลรอบสุดท้ายไม่มี error/warning

ยังต้องทดสอบความเข้าใจกับผู้ใช้จริง ไม่สรุปว่าการปรับรอบนี้ช่วยสภาพคล่องจริงหรือทำให้ใช้งานง่ายขึ้นจากการตรวจโค้ดเพียงอย่างเดียว
